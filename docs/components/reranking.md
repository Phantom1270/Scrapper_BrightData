# Cross-Encoder Reranking

After the hybrid search and fusion steps, the **doc//rag** system employs a Cross-Encoder Reranker (`CrossEncoderReranker`) to perform a final, high-precision relevance sort.

## 1. The Problem with Bi-Encoders
The initial dense retrieval step (ChromaDB) uses a Bi-Encoder (`all-MiniLM-L6-v2`). Bi-encoders independently embed the query and the document into vectors and compare their cosine distance. This is incredibly fast (allowing search across millions of documents in milliseconds) but lacks deep semantic understanding because the words in the query never interact with the words in the document during embedding.

## 2. The Cross-Encoder Solution
A Cross-Encoder feeds both the user's query and the document chunk into the Transformer model *at the same time* (e.g., `[CLS] User Query [SEP] Document Chunk [SEP]`). The attention mechanism computes rich interactions between every word in the query and every word in the document.

- **Model:** `cross-encoder/ms-marco-MiniLM-L-6-v2`
- **Mechanism:** Returns a single relevance score (float) rather than a vector.

## 3. Implementation in the Pipeline

1. **Candidate Limiting:** Because Cross-Encoders are extremely computationally expensive, we *cannot* run them on the entire database. The `RetrievalEngine` takes the top $K$ candidates (e.g., Top 20) generated by the RRF fusion step.
2. **Scoring:** The `CrossEncoderReranker` computes the exact relevance score for these 20 candidates against the user's original query.
3. **Re-sorting:** The candidates are sorted by their cross-encoder score in descending order.
4. **Final Cut:** The absolute top $N$ candidates (e.g., Top 5) are sliced and returned to the LLM for context generation.

## 4. Trade-offs
- **Advantages:** Substantially increases absolute precision. Documents that superficially matched keywords but lack real contextual relevance are pushed down the list.
- **Disadvantages:** High latency. Scoring just 20 documents can take 50-200ms depending on hardware. This feature can be toggled via `use_reranking: false` in the API payload for speed-critical applications.
